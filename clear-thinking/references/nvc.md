# 沟通：非暴力沟通四步

用于帮用户在冲突、不满、拒绝、被误解时，把情绪化的表达变成对方听得进去的表达。核心：把"观察""评价"分开，把"感受""想法"分开，说出需求，提出请求而非命令。

## 四个要素

1. **观察**：只描述录像机能拍到的具体事实，不带评价。
   - 评价式：你总是不回消息 / 你太不负责任
   - 观察式：这周我发的三条消息，你都没有回复
2. **感受**：说自己内心的情绪（担心、失落、委屈、焦虑、疲惫），不是对对方的评价。
   - "我感觉你不尊重我"其实是评价；"我感到失落"才是感受。
3. **需求**：感受背后，自己有什么需要没被满足（被重视、安全感、自主、休息、效率、理解）。
4. **请求**：具体、现在能做、正向表述、对方可以说不。
   - 命令：你以后必须及时回
   - 请求：忙的时候，能不能先回一个"收到"？

句式参考（不必死板）：当我看到/听到……，我感到……，因为我需要……。你愿意……吗？

## 工作流程

1. 读用户的原话或事件描述，标出：
   - 概括化（总是、从不、每次）
   - 贴标签/评价（懒、自私、不负责任）
   - 命令或要求口吻
   - 把感受归咎对方（都是因为你、你让我很生气）
2. 如果信息够，帮用户拆出四要素；缺哪个，问一个最关键的。
3. 给出改写版本。通常给 1 个主版本；如果用户和对方关系不同（亲密/同事/上级），可给两种语气。
4. 提醒发送前的自检：我现在想要"解决问题"还是"赢"？

## 同理心（倾听对方）

用户在冲突中想理解对方时，可以帮他猜测对方的观察、感受、需求：
"他是不是因为……而感到……，因为他需要……？"
用猜测的语气，让对方有机会纠正，不要下断言。

## 输出模板

**判断**：原话里容易激化冲突的点（引用原句）。
**拆解**：观察 / 感受 / 需求 / 请求（缺的标"待补"）。
**改写版本**：可直接发送的文字。
**发之前**：一句自检提醒。

## 注意

- 保留用户想表达的真实不满，别把改写变成讨好或无原则退让。
- 不替用户判断谁对谁错；用户要拒绝或设边界时，也可以用这个框架，把请求换成清晰的"我做不到/我选择不"。
- 涉及人身安全、持续的辱骂或控制时，沟通技巧不是首要问题，建议优先考虑安全和寻求专业支持。
